# Lab Setup

## Lab Architecture

- **Attacker/source:** Kali Linux
- **Victim/destination:** Windows machine
- **SIEM:** Splunk
- **Authentication:** SSH
- **Test account:** `itadmin`, intentionally configured as a local administrator

Use an isolated lab network. Do not use real credentials or perform these steps against systems without authorization.

## Windows Victim

Determine the Windows IP address:

```cmd
ipconfig
```

Record the confirmed address as `[INSERT WINDOWS IP]`.

Create a dedicated test account. Replace `<LAB_PASSWORD>` only in the local lab terminal; never publish the password in documentation, screenshots, or reports.

```cmd
net user itadmin <LAB_PASSWORD> /add
net localgroup Administrators itadmin /add
```

The account is intentionally privileged so that the resulting authentication can be investigated as a privileged login. Verify group membership locally and capture evidence without exposing secrets:

```cmd
net user itadmin
net localgroup Administrators
```

Record the account creation time, membership result, and Windows hostname as evidence placeholders:

- Account creation time: `[INSERT TIMESTAMP]`
- Administrators membership: `[INSERT OUTPUT OR SCREENSHOT]`
- Windows hostname: `[INSERT HOSTNAME]`

## Kali Linux

Kali is the controlled source system. Determine or confirm its address using the local network tools available in the lab, then record it as `[INSERT KALI IP]`.

Test connectivity to the Windows host:

```bash
ping -c 3 <WINDOWS_IP>
```

Do not treat a failed ping as proof that SSH is unavailable; firewall policy may block ICMP. Test SSH only against the authorized lab host:

```bash
ssh itadmin@<WINDOWS_IP>
```

Do not publish the password. Record the confirmed source address, destination address, and connection timestamp.
