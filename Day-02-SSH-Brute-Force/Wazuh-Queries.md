# Wazuh Queries

These Wazuh DQL queries were used during the controlled Day 02 lab investigation.

## Authentication Failures

### Query

```text
rule.groups:authentication_failed
```

### Purpose

Find authentication-failure alerts.

### What it Finds

Events grouped as authentication failures, including SSH and PAM failures.

### Evidence From My Investigation

The Wazuh dashboard showed authentication-failure activity associated with the lab SSH test.

## PAM Login Failures

### Query

```text
rule.id:5503
```

### Purpose

Find PAM user login failure events.

### What it Finds

`PAM: User login failed.` events generated by rule `5503` at level 5.

### Evidence From My Investigation

Four hits were visible in the specific rule `5503` query result.

## SSH Authentication Failures

### Query

```text
rule.id:5760
```

### Purpose

Find SSH daemon authentication failure events.

### What it Finds

`sshd: authentication failed.` events generated by rule `5760` at level 5.

### Evidence From My Investigation

Multiple events were visible and were associated with SSH authentication failure activity.

## Correlation

### Query

```text
rule.id:(5760 OR 5503)
```

### Purpose

Correlate SSH authentication failures with PAM login failures.

### What it Finds

Events matching either the SSH rule or the PAM rule.

### Evidence From My Investigation

Twenty-seven hits were visible in the selected time range. This is a Wazuh search-result count, not the exact number of Hydra attempts.

## Source and Target Pivot

### Query

```text
Failed password for testuser from <LAB_SOURCE_IP>
```

### Purpose

Search for events associated with the same target account and identified lab source.

### What it Finds

Related failed-password messages that can be correlated by source and target account.

### Evidence From My Investigation

Sixty-nine hits were visible in the selected time range. This pivot is useful for correlation but can include related authentication activity; it is not an exact Hydra-attempt count.

## Authentication Success

### Query

```text
rule.groups:authentication_success
```

### Purpose

Check whether successful authentication occurred and determine whether failed attempts led to compromise.

### What it Finds

Authentication-success events that require correlation with timestamp, source, target account, and SSH context.

### Evidence From My Investigation

Authentication-success events were visible and were reviewed separately. They were not assumed to belong to the Hydra activity without matching context. The Hydra test itself found 0 valid passwords.

## Investigation Mapping

| Query | Investigation Purpose | Evidence |
|---|---|---|
| `rule.groups:authentication_failed` | Identify authentication-failure activity | Wazuh dashboard showed authentication failures. |
| `rule.id:5503` | Identify PAM login failures | Rule `5503`; 4 hits in the specific result. |
| `rule.id:5760` | Identify SSH daemon failures | Rule `5760`; multiple SSH failure events. |
| `rule.id:(5760 OR 5503)` | Correlate SSH and PAM failures | 27 hits in the selected range; not the Hydra count. |
| `Failed password for testuser from <LAB_SOURCE_IP>` | Pivot on source and target | 69 hits in the selected range; useful for correlation, not an attempt count. |
| `rule.groups:authentication_success` | Check for possible successful access | Success events require context correlation; no valid password was found by Hydra. |

## Investigation Notes

The controlled Hydra test generated 6 password attempts and found 0 valid passwords. Wazuh counts above describe search results for their selected time ranges and must not be conflated with the simulation count.
